## Web通信
前后端之间的通信，本质上是问答：前端发请求，后端回响应。请求和响应中携带的各种附加信息，主要放在请求头和响应头里，像身份凭证、内容类型、缓存策略这些。

最典型的例子是 Cookie：服务端通过响应头中的 Set-Cookie 下发，浏览器随后会在请求头的 Cookie 字段中自动携带。这样服务端就知道每次请求对应的用户。

前端可以是粗糙的，但后端要精致些：面对每个请求，至少需要经过如下中间件的处理：跨域处理、分配uuid、鉴权、限流、以及写日志。这些在SpringBoot中是通过引入依赖、修改配置实现，在Gin中需要自己去手写这些中间件。

我认为 Gin 是一个很轻量的框架,这在很大程度上得益于：1.标准库net/http已经足够完善，2.Go本身的语言设计没有 Java、C++ 那样的类继承体系,goroutine 的特性;以及编译后为二进制文件。这些让代码变得易懂，并发变得低廉，环境配置变得简单。

Gin通过`go.mod`来进行依赖管理，除了标准库像fmt、os、time这些标准库外，还要谷歌的uuid库来进行请求ID生成，uber公司开源的zap库进行日志管理。随着业务的逐渐臃肿，引入的库也会越来越多。

最核心的部分是 gin.Engine。它是Gin框架的引擎,负责路由维护、中间件注册,并把收到的 HTTP 请求分发给对应的处理函数。下面就是个很小的实践：
```golang
r := gin.New()  // 实例创建
// 中间件注册
r.Use(middleware.RequestID(), middleware.Logger(), middleware.Cors()) 
// 函数绑定
r.GET("/ping", func(c *gin.Context) {
    c.JSON(200, gin.H{"msg": "pong"})
})
// 运行实例
r.Run(":8080")
```

这里的中间件都是自定义实现的。接下来是跨域处理、分配 UUID、鉴权、限流和日志记录这几个中间件的代码与思路，或许能增进你的理解。

Gin用gin.context表示请求的上下文对象，这个对象包含下面这些函数
| 分类 | 功能 | 说明 | 示例 |
|---|---|---|---|
| 读取请求信息 | 获取客户端 IP | 获取请求来源客户端 IP | `c.ClientIP()` |
| 读取请求信息 | 获取请求头 | 读取指定请求头 | `c.GetHeader("X-Request-ID")` |
| 读取请求信息 | 读路由参数 | 如 `./users/:id` 里的 `id` | `c.Param("id")` |
| 编辑响应信息 | 返回 JSON | 返回 JSON 响应 | `c.JSON(200, gin.H{"ok": true})` |
| 编辑响应信息 | 返回纯文本 | 返回字符串响应 | `c.String(200, "hello")` |
| 编辑响应信息 | 设置状态码 | 设置 HTTP 状态码 | `c.Status(204)` |
| 编辑响应信息 | 设置响应头 | 设置响应头字段 | `c.Header("X-Request-ID", id)` |
| 中间件 | 存值进 `map` 字段中 | 在上下文中保存值 | `c.Set("userID", 123)` |
| 中间件 | 读取 `map` 字段中值 | 返回 `(any, bool)` | `c.Get("userID")` |
| 中间件 | 跳过中间件 | 继续执行后续处理 | `c.Next()` |
| 中间件 | 终止中间件 | 终止后续处理 | `c.Abort()` |
| 中间件 | 终止并返回 JSON | 终止并返回 JSON 响应 | `c.AbortWithStatusJSON(401, ...)` |
### UUID分配
生成随机uuid的函数源自谷歌的UUID库，形式大概是这样：9b2f4c1e-7a3d-4b8e-9c6f-2d1a0e5f8b7c
```golang
import ("github.com/google/uuid")
func New() string {
	return uuid.NewString()
}
```

最终的中间件函数是这样的,值得一提的是:代码中莫名出现的middleware、reqid是包名，即`package reqid`，意思是通过包名调用这个包里对应的函数(有点像Java的设计)。
```golang
const Header = "X-Request-ID"
func RequestID() gin.HandlerFunc {
	return func(c *gin.Context) {
        // 请求头查询
		id := c.GetHeader(reqid.Header)
		if id == "" {
            // 生成uuid
			id = reqid.New()
		}
        // 存值进入map字段
		reqid.Set(c, id)
        // 响应头字段
		c.Header(reqid.Header, id)
		c.Next()
	}
}
```

对于装配，仅需要简单一句就好。
```golang
r.Use(middleware.RequestID())
```
### 日志配置
在一些科幻影视作品涉及破解的情节中，电脑常冒出大片数据流，而这些数据流的一个主要组成部分就是日志。那么日志应该向阅读者暴露出哪些信息呢？

基础的有时间，日志级别，日志内容，日志Id，进阶些则包含自定义字段：像是请求IP，响应状态，请求路径，请求方法和耗时等等。

通常情况下不使用标准库log，因为它有全局互斥锁，这让日志打印只开一条线程，不适用于高并发。因此选用的是uber公司开源的`zap`日志库。其特点是：1.零内存分配 2.`json`格式 3.`Info`、`Warn`、`Error`、`Debug`四种日志等级。

对应的中间件函数是这样实现：
```golang
func AccessLog(log *zap.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		start := time.Now()   // 时间记录
		path := c.Request.URL.Path  // 路径记录
		if raw := c.Request.URL.RawQuery; raw != "" {
			path = path + "?" + raw
		}

		c.Next()

		// 自定义 JSON形式的字段对象
		fields := []zap.Field{
			zap.String("request_id", reqid.Get(c)),
			zap.String("method", c.Request.Method),
			zap.String("path", path),
			zap.Int("status", c.Writer.Status()),
			zap.Duration("latency", time.Since(start)),
			zap.String("ip", c.ClientIP()),
			zap.Int("size", c.Writer.Size()),
			zap.String("user_agent", c.Request.UserAgent()),
		}
		if len(c.Errors) > 0 {
			fields = append(fields, zap.String("errors", c.Errors.String()))
		}

		switch {
		case c.Writer.Status() >= http.StatusInternalServerError:
			log.Error("http request", fields...)
		case c.Writer.Status() >= http.StatusBadRequest:
			log.Warn("http request", fields...)
		default:
			log.Info("http request", fields...)
		}
	}
}
```
