后端框架很多。我之前粗略学过 Java 的 Spring Boot，但总觉得它过于规范、封装太深，很多东西都被提前定好了。说好听点是企业级全栈生态；说难听点，写起来班味太浓。

最近我接触并学了阵子 Go 的 Gin框架，发现它很对我的胃口：极简，只负责 HTTP 路由、中间件等，其余部分都要自己搭建，让我有种很舒服的掌控感。

当然，以上纯属我个人的浅薄感受。两者本质上都是 Web 框架，要解决的问题是一样的，只是风格和取舍不同。接下来就聊聊用 Gin 搭的一个基础脚手架，需要做到哪些事情。
## Web通信
前后端之间的通信，本质上是问答：前端发请求，后端回响应。请求和响应中携带的各种附加信息，主要放在请求头和响应头里，像身份凭证、内容类型、缓存策略这些。

最典型的例子是 Cookie：服务端通过响应头中的 Set-Cookie 下发，浏览器随后会在请求头的 Cookie 字段中自动携带。这样服务端就知道每次请求对应的用户。

前端可以是粗糙的，但后端要精致些：面对每个请求，至少需要经过如下中间件的处理：跨域处理、分配uuid、鉴权、限流、以及写日志。这些在SpringBoot中是通过引入依赖、修改配置实现，在Gin中需要自己去手写这些中间件。

我认为 Gin 是一个很轻量的框架,这在很大程度上得益于 Go 语言本身的设计：Go 没有 Java、C++ 那样的类继承体系,也没有注解,因此代码流程直观;同时goroutine 让并发变得简单而低廉;最终编译后是二进制文件,部署时不需要额外的运行环境。
