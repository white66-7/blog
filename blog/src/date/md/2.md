## 最大Bug
值得一提的题外话是为什么漏洞会叫Bug-飞蛾呢？原因是早期编程其实非常原始，所谓的计算机完全靠继电器组成，这个黑色，巨大又温暖的机器会吸引昆虫。

1947年9月，哈佛马克2号故障继电器中拔出了一只飞蛾，飞蛾拔出后计算机就恢复了运行，因此后续当计算机故障或程序错误人们都称为出bug了。这个冷知识是我刚进入大学时看<a href="https://b23.tv/m4QfPdW" target='_blank' rel="noopener noreferrer">计算机速成课</a>学到的，我认为这个合集非常有趣并且有深度，推荐给那些准备选计算机专业的朋友看看。

我的最大Bug是每次我的歌曲靠点击或拖拽存入时，我直接在数据库里塞进去了一份同样的文件。
```typescript
t.objectStore(S_STORE).put({
    id: s.id,
    signature: s.signature,
    name: s.name,
    artist: s.artist,
    originalFileName: s.originalFileName,
    directoryId: s.directoryId,
    file: s.file   //存的是 File 对象
});
```
在歌曲数量极少的情况下当然是可行的，但是一个歌曲文件flac格式大概在20多MB的量级，而IndexedDB只支持5GB的数据存量。

另外就是我的数据库的数据管理非常烂，当我每次查询我的数据库时，即使我已经删光了所有的歌曲，我的dirs还保存着一堆数据。
```typescript
async function delSingle(id) {
    if (!confirm('确认永久删除该音频？')) return;
    const idx = library.findIndex(s => s.id == id);
    if (idx === -1) return;
    //从内存的歌曲数组里删掉这首歌
    library.splice(idx, 1);
    //从数据库的歌曲表 (S_STORE) 里删掉这首歌
    if (idbOK) await delSong(id);
    // ...处理播放器 UI 和 进度条的逻辑
}
```
原因就是我对我的数据库创立了哪些组其实并不了解，我忽视了我其实还创造了一个D_STORE表，这个表会无限制地存入数据，并且无法删除。
##  架构与工程化
这个其实是我的顽疾，我一开始写的那个火影格斗小游戏也是这样，一共两千行的代码，实际的main主逻辑链条其实就100来行。

每次我要给人物加一些新的东西比如跑动，瞬身都要划来划去的找对应的类，对应的函数。非常麻烦。

这个也犯了同样的错误，1000 多行的文件，HTML、CSS、JS全部揉在一个index.html里，正确的做法是，拆出来style.css和一堆逻辑js，比如说处理歌曲文件封面的cover.ts,处理删除逻辑的del.ts等等，这样每次更新其实会方便很多。

最难评的是，由于是新手，我的块级DOM节点全写的div，上次刷到一篇文章说这种代码就是给视障人士和屏幕阅读器喂屎。

能做的改进是语义化DOM。这让我在后续的Vue开发中收益良多。
```text
<div class="sidebar">可以用<aside>
<div class="top-bar">可以用<header>
<div class="main">可以用<main>
<div class="scroll-list">可以用<ul> 和 <li>
```
