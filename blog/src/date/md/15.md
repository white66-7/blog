## 引论
说实话，以我现在的经验来说，我觉得加载屏是一个绝佳练Vue框架熟练度的小项目。

因为它包含许多我们常常用到的特性，比如说前后端连接，paine，路由rounter，css动画，基本的typescript函数。

于此同时，他的界面设计简单，进度条，进度提示等等这些的组合，便于入手；

最后作为一个网页项目，加载屏美化了网页的同时，还能实现必要的功能。
## 多屏逻辑
分析一下加载屏的需求：在访问者进入界面时播放动画，同时后台加载必要资源，并且仅仅触发在初始的网页加载，而非各个路由加载。

那么写在哪里呢，这是一个值得思考的问题？

其实也就两个选择，App.vue还是index.html。

这两种选择各有利弊，如果是index.html，好处是网页加载时第一步加载的就是index.html，你的加载屏可以急速呈现。

但是你要用前端三件套原生的语法来写所有的逻辑，带来的问题是：我们的网页项目是靠Vue框架写的，index.html处于Vue外部，无法访问Pinia和Router，那么加载屏消失的时候页面可能首先是一片空白，假设你不在乎这个，那么接下来要面临的问题是组件销毁的问题，这个氛围两种情况，如果你写在app里面，销毁时几乎无法实现什么动画，切换非常生硬，如果写在app外部，就要自己在typescript手动添加类名，添加DOM节点。

如果是写在App.vue中，那么加载时不可避免会出现0.1-0.2秒的白屏来加载index.html，后续vue项目挂载，加载屏才出现。优点是加载屏可以完全作为一个子路由来控制管理，切换页面时可以有动画的实现效果。并且script部分下的函数部分会好写很多。
## 函数逻辑
加载屏其实有很多样式，我在一些素材网站上搜寻了很久，举几个例子：手写书法文字，印章盖印动效，转圈动画，进度条，日志展出等等。

我们可以自由编排组合这些以达到不错的效果。

### "熟人"逻辑
第一次加载怕屏动画完成后，后续用户刷新或是后台重启时，网页的资源其实已经加载完毕了。这时候不需要去浪费资源去完成加载逻辑了，直接让加载屏动画一闪而过是一个很好的选择。
```typescript
const isFastMode = sessionStorage.getItem('splash_shown') !== null
sessionStorage.setItem('splash_shown', 'true')

const MIN_DISPLAY_TIME = isFastMode ? 300 : 2600
```
其中sessionStorage特性就相当于一个网页的记事本，初次进入网页时，sessionStorage啥也没有，这是isFastMode得出False的值，那么动画最少持续时间MIN_DISPLAY_TIME为2600毫秒。
以后再进入时sessionStorage通过setItem函数新增了一个键值splash_shown对应的值是true。动画最少持续时长就是300毫秒了。
### 路由加载
路由的加载逻辑其实和字体，图片的加载逻辑如出一辙。都是用一个变量来记录一整个加载事件的返回值，后续在OnMounted拿这个返回值判断加载完成与否。

值得一提的是Vue框架的特性，路由加载其实很简单。
```typescript
import { useRouter } from 'vue-router'
const router = useRouter()  //先返回一个Promise

const routerPromise = router.isReady()
```
接着判断
```typescript
Promise.all([
    imagePromise,
    fontPromise,
    routerPromise
]).then(async () => {
    const elapsed = Date.now() - startTime
    const delay = Math.max(MIN_DISPLAY_TIME - elapsed, 0)

    await sleep(delay)
    exitSplash()
})
```
Promise在我看来贴切的解释是强制等待这些任务的完成，之后then指示强制等待多少秒，之后触发退出动画。
### 图片加载
通过一个数组，子元素是图片加载靠的是创建一个浏览器原生的Img节点，这个节点不用于展示，就纯纯加载下来到浏览器缓存中去，等下次真正要用的时候直接拿就好。
```typescript
const imagePromise = Promise.all(
    imagesToLoad.map(url => new Promise((resolve) =>{
        const img = new Image()
        img.src = url
        img.onload = resolve
        img.onerror = resolve
    }))
)
```
imagesToLoad是一个数组，子元素全是图片的地址，即这里的url，这里区别于forEach，选择用map的原因是map可以修改原数组生成一个新数组，所以代码量会少一些。

通过img.src = url赋值地址后再通过img.onload加载就可以实现提前加载。
### 字体加载
通过一个变量拿到异步函数的执行结果，然后放到Promise.all中等待
```typescript
const fontPromise = (async () => 
{
    try{
        if(document.fonts)
        {
            await document.fonts.load("...")
        }
    }
    catch (error){
        console.warn('失败',error)
    }
})()
```
这个函数其实借助了javascript的特性document(总控台)，我们可以通过document拿到所有图片合集，表单合集，查找类等等操作，这里拿的是字体fonts
## 动画逻辑
强一点的人可能会把动画写成响应式播放，即加载到哪播放到哪，但是我觉得这没啥必要。

我的动画其实是一个写好的动画，字什么时候写好，什么时候出现印章都是固定的。

变化的是播放的时间。第一次保底是2.6秒，2.6秒之后还在加载就继续播放，从此以后就固定0.3秒一闪而过了。

我感觉两种选择各有优缺点。
