### 开机自启动
开机自启动对这个工具应用场景无疑是有必要的，那么怎么实现呢？看完这两篇文章(需要科学上网)，或许你对开机自启动的理解会深刻些。

这篇文章讲了一个罕见的自启动底层Bug以及基础的自启动模式。<a href="http://windowsir.blogspot.com/2022/07/does-autostart-really-mean-autostart.html" target='_blank' rel="noopener noreferrer">“自动启动”真的就是“自动启动”吗？</a>

这个则是一个完整的审计指南，讲解了自启动的机制<a href="https://github.com/0xDarkMatter/claude-mods/blob/main/skills/windows-ops/references/startup-mechanisms.md" target='_blank' rel="noopener noreferrer">Windows 开机自启动机制</a>

为了达成目标，首先要写一个函数检测应用是否已经自启动，每次我们启动或者取消的时候都要去查询一下，避免产生残留。接着写开启与取消自启动函数，让用户在设置界面通过按钮调用。

查询需要借助Python的winreg库，通过这个库我们可以访问和操作Windows注册表，这个库中的OpenKey可以打开注册表键，QueryValueEx函数可以查询键下的值。
```python
key = winreg.OpenKey(winreg.HKEY_CURRENT_USER, '注册表路径', 0, winreg.KEY_READ) # 以只读方式打开当前用户的Run键，拿到句柄
winreg.QueryValueEx(key, ‘要查询的程序名’)  # 在已打开的 key 中查询
```
拿到了就返回True，拿不到就返回False。忽略了状态数据和数据移动的问题，导致任务管理器的应用启用状态不对应。具体的函数我想就不在这里列出来了，有点复杂和啰嗦。步骤就是我要去查Run键里是否存在本应用的值；Run 值指向的程序路径是否仍然存在；StartupApproved 的标记是不是“禁用”。

同样的，借助SetValueEx函数去改写应用程序的值开启自启动。
```python
winreg.SetValueEx(key, APP_NAME, 0, winreg.REG_SZ, ‘程序文件的地址’)
```
这样其实并不保险，所以我后面加了一步擦除StartupApproved禁用标记。

最后，禁用靠的是DeleteValue函数，直接删除键值。
```
winreg.DeleteValue(key, APP_NAME)
```
这样不太优美，所以我改成了模拟原生的保留Run键，写入StartupApproved禁用标记来禁用。
### 下载器
和众所周知的EA启动器是差不多概念，当实际运行文件体积较大时，会有下载过程因频繁中断而失败，且中断后临时文件被自动清除的差体验。

运行主要的逻辑是创建目录 -> 获取文件 -> 下载文件 -> 创建快捷方式。一般我们还要旧版本检测，进度条，权限检查等次要功能。

创建目录是很简单的一个语句，我把它写成一个函数来增强可读性。在传入的磁盘地址新建一个文件夹放我们的运行文件。
```python
import os  # 原名 operate system

def create_dir(path):
  os.makedirs(path,exit_ok="False")  # makedirs可以创建多级目录
```
获取文件，这个操作本质上是一次网络请求，有点讲究的地方在于要保证网络安全，要对传输的数据进行加密，验证访问网站的证书安全性。这两个操作依靠Python的两个内置库ssl(保证安全性)和urllib来实现(网络请求操作)，并且这个urllib的使用操作就和大一学的文件访问操作一般。
```python
import ssl  
import urllib
def download_file(url,path):
  ctx = ssl.create_default_context() # 创建安全上下文
  ctx.check_hosthome = False # 关闭主机名验证
  ctx.verify_mode = ssl.CERT_NONE # 关闭证书验证 cret即certificate的缩写
  req = urllib.request.Request(url,headers = {"User-Agent": "Mozilla/5.0"}) # 加一个请求头，伪装成正常的浏览器访问
  with urllib.request.urlopen(req,context = ctx) as response,open(path,'wb') as f:
    date = response.read() # 读取地址
    f.write(date) # 写入对应文件夹
```

### 一键隐藏方式
这个的话就不是很有复用性了，代码逻辑就是先拿到点击的坐标，获取双击区域对应窗口的PID和类名，第一层判断是看PID是否explorer.exe进程的，且类名与桌面相关。这能筛查出弹窗区域的点击。第二层判断是把坐标发给explore.exe进程的LVM_HITTEST，然后去看返回结果判定是否点到了快捷图标上。

用到了两个系统的dll分别是user32和kerne132，一个是负责窗口相关操作，一个负责系统进程相关操作。

值得一提的是，我原本的判断是一整根链条，创建一个数组，第一次点击直接存入，第二次点击判定相隔时间，不对数组直接清零，对的话就去看上面两层判断的返回结果，对的话就调用user32的PostMessafeW函数来执行图标全隐藏操作。
```bash
user32.PostMessageW(self.desktop_sv, 0x0111, 0x7402, 0) # 0x7402就是指令
```
但是这样存在的问题是：点击频率一上来，发生诸如第二次和第三次莫名组合的问题，变得很混乱，并且老实说这样占用的运行内存也稍微大了一些，后面改成了两个线程，一个专门用来存点击，一个专门用来判断，数组换成队列，每次取两个拿去判断。我认为这是一次很好的重构优化。

## 运行日志
存放log文件的位置有两个选择，一个是同目录下，另一个是%APPDATA%\DesktopHelper下，%APPDATA%\文件夹是专门用来存放应用运行日志的地方，会稍微正式一些。

那么Python的运行日志一般是靠内置库logging来实现的，我们可以在一开始设置文件位置，日志级别，和日志名称。
```python
import logging
appdata = os.path.expanduser('~\\AppData\\Roaming') #这个就是%APPDATA%\
data_dir = os.path.join(appdata, "DesktopHelper") # 为了后续新建一个文件夹
 
logging.basicConfig(
  filename = date_dir,  # 靠这个把日志放到合适的位置
  level = logging.DEBUG 
  format = '%(asctime)s [%(levelname)s] %(message)s' # 输出格式 时间 级别(info/error等) 消息
)
```
后续传入数据只要调用logging的内置函数就可以了
```python
logging.info("已经结束了")
logging.debug("在调试一下")
logging.warning("不对，有问题")
logging.error("真出问题了")
```
