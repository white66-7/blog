## 文章跳转的动态路由
接下来说回正题吧，我们都知道vue框架下的页面跳转是写死在index.ts文件中的，但是随着文章数量增多，如果每一篇文章都自己手动去写一个路由那么代码未免又太过于冗长。

解决办法是我们可以充分发挥路由的特性写一个动态路由来统一管理这个跳转。

首先来看看我的文章仓库是怎样的吧？
```typescript
export interface Article {
  id: number
  title: string
  type: string
  date: string
  excerpt: string
  tags: string[]
  cover: string
  content: string   
}
```
这里的id每个文章独一份

第一步是给你展示的每个文章卡片绑定的点击事件
```typescript
<div v-for="article in paginatedArticles" @click="goToArticle(article.id)">
const goToArticle = (id: number) => {
  router.push(`/article/${id}`)
}
```
可以看到对这个页面的所有文章即paginatedArticles，每篇文章都取出获取这篇文章的id传给goToArticle函数，这时候地址转变为/article/id

接下来我们要在路由里写代码
```typescript
path: '/article/:id',
name: 'ArticleDetail',
component: ArticleDetail
```
其中:id是动态占位符，只是说明地址是这样的形式。无论是哪个路径都交给ArticleDetail组件来加载

接着是ArticleDetail组件的逻辑，首先要先从路由中获取id
```typescript
import { useRoute } from 'vue-router'

const route = useRoute()
const id = Number(route.params.id)
```
通过params拿到所有的动态占位符，这里parms对应的是{ id: ...},接着通过键值id拿到对应的值，这里就是要显示的文章id。

接着在传来的文章仓库找对应id的文章
```typescript
import { articles as allArticles } from '@/date/articles'

onMounted(async () => {
  const id = Number(route.params.id)
  article.value = articles.find(a => a.id === id) || null
  }
```
这里article的值就是文章仓库里对应的那篇。每次加载网页的时候就拿到这篇文章的相关信息，接着把他的content拿去渲染。
## 内容渲染
我的每篇文章都写在md文件中，用的是markdown语法，整条链路为原文通过`markdown-it`渲染输出v-html，与主流稍有不同的是，我的md文件放在了前端文件夹里面，由于文本是静态的，所以我觉得不通过后端api调用会更快也更简单，主流的做法是把文本内容放到后端，通过api访问拿到，前端渲染之后呈现在网页上。

无论是哪种放法都不影响前端的渲染逻辑，这是通用的。

markdown解析是通过引入外部库<a href="https://github.com/markdown-it/markdown-it" target="_blank" rel="noopener noreferrer">MarkdownIt</a>实现的，它可以把markdown文本解析为html文档。

首先创造一个实例对象
```typescript
// 导入
import MarkdownIt from 'markdown-it'

const md = new MarkdownIt({ html: true })
```
### markdown-it
在 AI 时代，token 是一个绕不开的概念。markdown-it 里的 token 和 LLM 里的 token 相通的地方在于：把一段连续文本切成带类型的片段。LLM 切出来的是词元，markdown-it 切出来的是结构单元，原文的经过处理后每段内容被打上类型标签，这个标签就是 token 的 type。
```typescript
// markdown-it 内部定义的类
class Token {
  constructor(type, tag, nesting) {
    this.type = type          // string
    this.tag = tag            // string
    this.attrs = null         // [ [name, value], ... ]
    this.map = null           // [ startLine, endLine ]
    this.nesting = nesting    // 1 | 0 | -1
    this.level = 0            // number
    this.children = null      // Token[] | null
    this.content = ''         // string
    this.markup = ''          // string
    this.info = ''            // 专为fence设计
    this.meta = null          // any
    this.block = false        // boolean
    this.hidden = false       // boolean
  }
}
```
token的type是理解入口，粗略分为文本、代码块、标签、行内容器及图片这几种类型。这几种类型拥有独特的字段；
- `type` 为`heading_open`时表示开标签
	- ```TypeScript
	  {
	    type: 'heading_open', 
	    tag: 'h2',  // html中 <h>
	    nesting: 1,
	    level: 0,
	    content: '',        // 空字符串
	  }
	  ```
- `type` 为`inline`时表示行内容器
	- ```TypeScript
	  {
	    type: 'inline',
	    content: '这是 **加粗** 的文字',   //原始字符串
	    children: [   // 解析后 token
	      { type: 'text', content: '这是 ' },
	      { type: 'strong_open' },
	      { type: 'text', content: '加粗' },
	      { type: 'strong_close' },
	      { type: 'text', content: ' 的文字' }
	    ],
	    ...
	  }
	  ```
- `type` 为`image`时表示图片
	- 属性信息在 attrs 中
	- ```TypeScript
	  {
	    type: 'image',
	    tag: '',
	    nesting: 0,
	    level: 1,
	    content: '',    // 图片无文本内容
	    attrs: [       // 实际信息在属性中
	      ['src', '/messages/1/11.webp'],
	      ['alt', '点击显示']
	    ],
	    children: [ { type: 'text', content: '点击显示' } ],  // alt的源文本
	    ...
	  }
	  ```
- `type` 为`fence`时表示代码块
	- ```TypeScript
	  {
	    type: 'fence',
	    tag: 'code',
	    content: 'int main(){}\n',   // 代码正文
	    children: null,              // 无子 token
	    info: 'cpp',                 // 语言标识
	    ...
	  }
	  ```
- `type` 为`text`时表示正文
	- 此时只有正文有意义
	- ```TypeScript
	  {
	    type: 'text',
	    content: '这是占位的',
	    ...
	  }
	  ```
原文通过遍历后得到这样一长段Token文本，接着输入render函数进行渲染输出HTML文档。

渲染依靠结构单元的type，通过查找`md.renderer.rules`字典拿到对应的渲染函数，渲染后输出对应的文本。正常的渲染函数大概是下面的形式：类型匹配、字段取用、HTML文档输出。

值得一提的是，通过自定义渲染函数可以修改渲染样式。下面是为了实现语法高亮对于代码块的自定义渲染——依靠`highlight.js`包的highlight函数
```typescript
import hljs from 'highlight.js'

md.renderer.rules.fence = function (tokens, idx) {
  const token = tokens[idx]
  if (!token) return ''
  
  const code = token.content || ''

  const rawLang = (token.info || '').trim()
  const displayLang = rawLang.toUpperCase() || 'CODE'
  let hljsLang = rawLang.toLowerCase()
  
  // 语言归一化
  if (hljsLang === 'c++') hljsLang = 'cpp'

    }

    highlightedCode = md.utils.escapeHtml(code)

### HTML挂载
接着用vue的响应式特性绑定文章的实际内容，在文章内容变动时自主更新。函数里的内容是一个三元表达式，如果article.value不为空，就返回md这个对象通过render方法，解析article值的content对应的md文件得到的html文档，否则就为空字符串。算是一个安全兜底。
```typescript
const renderedContent = computed(() => (article.value ? md.render(article.value.content) : ''))
```

得到了html文档就要把它嵌套到实际显示的html文档中
```typescript
<div class="markdown-body" v-html="renderedContent"></div>
```
其中v-html是Vue提供的一个内置指令，可以把输入的内容嵌套进去。

接着就是给渲染出来的一级标题，二级标题，正文部分添加漂亮的样式。可以看到这个类叫markdown-body

那么deep是用来干嘛的呢？

由于这段插入的html文档其实是动态生成的，而style设置的scoped属性，导致样式无法作用于这段动态内容。

因为v-html动态生成的h1，h2等等，Vue不会自动给它加上特殊的data-v-xxx属性，相当于这些内容没有“身份证号”。

加上deep后就相当于一层穿透，不管有没有“身份证号”，只要是markdown-body内的一级标题等就用这个样式

## 目录生成与跳转
涉及这个目录的逻辑是抓取到渲染到跳转

抓取函数是下面这样的
```typescript
function buildHeadings() {
  if (!contentRef.value) return  //安全检测
  const els = contentRef.value.querySelectorAll('.markdown-body h1, .markdown-body h2')    //在渲染出来的html文档里找.markdown-body下的h1和h2
  headings.value = Array.from(els).map(el => ({  //headings数组里面保存数据
    text: (el as HTMLElement).textContent || '', //标题文字
    level: Number((el as HTMLElement).tagName.charAt(1)), //charAt是获取索引为1的元素(H1则拿1)
    el: el as HTMLElement                         // el认定为一个HTML元素,保存这个对象为el
  }))
}
```
抓取存到headings的内容后遍历渲染到html文档中
```html
<a v-for="(h, i) in headings" 
   :key="i" 
   class="toc__item" 
   :class="{ 'toc__item--active': activeHeading === i }"  
   :style="{ paddingLeft: (h.level - 1) * 12 + 'px',
            fontSize: (20 - h.level * 2) + 'px'
   }"       对应缩进和字的大小不同
   @click.prevent="scrollToHeading(i)">
  {{ h.text }}
</a>
```
其中i是索引，key算是固定搭配了，@click.prevent阻止a标签的默认行为：页面跳到顶部

点击后触发跳转函数scrollToHeading
```typescript
function scrollToHeading(index: number) {
  const h = headings.value[index]
  if (!h) return
  const top = h.el.getBoundingClientRect().top + window.scrollY - 80 
  window.scrollTo({ top, behavior: 'smooth' }) //窗口的跳转函数
}
```
这里h的el指的就是实际文章中的那个标题的位置，这个top就是往下滚动多少像素。计算公式为元素距离屏幕最上方的距离+当前已经滚动距离- 导航栏的高度(80)
## 英文与中文间空格的自动化实现
这个是排版美化函数，用于在md文档渲染前自动在中文和英文间加空格。实现操作是：对文本遍历,找到所有的代码块、LaTex数学公式,将他们暂存在数组后删除，接着对正文进行加空格操作。

### 正则表达式
这涉及进阶一点的正则表达式和回调函数的知识，<a href="https://regex101.com/" target="_blank" rel="noopener noreferrer">正则表达式预览网站</a>，在这个网站或许会看得清楚一些。

这个函数靠将代码块、LaTex数学公式替换为密钥，后面在靠密钥再替换回来。整体代码如下
```typescript
// 四个要被替换的部分
const PROTECT_RE = /```[\s\S]*?```|`[^`\r\n]+`|\$\$[\s\S]*?\$\$|(?<!\\)\$(?!\s)([^\$\n]+?)(?<!\s)\$/g

function addSpace(text: String): string{
  if(!text) return ''
  const placeholders: string[] = []
  // 替换过程
  text = text.replace(PEOTECT_RE,(match,inlineFormula) =>{
    const key = `${PH_PREFIX}${placeholders.length}${PH_SUFFIX}`

    if (inlineFormula !== undefined) {
      placeholders.push(`$${inlineFormula.trim()}$`)
    } else {
      placeholders.push(match)
    }
    return key
  })

  text = text
  .replace(HAN_ALPHANUM_RE, '$1 $2') // 英文后跟汉字
  .replace(ALPHANUM_HAN_RE, '$1 $2') // 汉字后跟英文
  .replace(ESCAPE_SLASH_RE, '\\\u200B') //斜杠后跟数字，英文

  text = text.replace(RESTORE_RE, (_, idx) => placeholders[Number(idx)] ?? '')
}
```
