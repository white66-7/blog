## 前言
经过一年半断断续续的学习，我对前端、后端是什么，算是有了个基本的认识。浏览器输入域名后的跳转，登录QQ后实时更新的消息，还有生活中离不开的各种APP，它们究竟是依靠什么搭建起来的呢？接下来就来说道说道这回事。
## 进程与线程
进程，是一段正在运行的程序：点击 APP 的可执行文件后，操作系统把它加载进内存用于CPU调用，分配内存和其他资源，让它运行起来。而线程是进程里最小的执行单位，同一个进程里的线程共用内存，可以自由读写所属进程的资源，比如音乐软件里可以有下载线程、播放线程、界面响应线程等等。

进程之间的内存与资源是相互隔离的，本机上的两个进程，有点像移动端各自的沙盒环境。要想通信，就得借助操作系统提供的通道，也就是 IPC，常见的有消息队列、管道和共享内存。而互联网中，要解决的是两台联网设备上各自独立的进程之间的通信。

在浏览器输入网址按下回车后，浏览器内部的代码会把输入的内容补全成完整的网络请求，根据域名解析出的IP地址，发送给对应的服务器。服务器有一套处理请求的逻辑，面对请求发送对应的数据。这件事的本质是：电脑上的浏览器进程，和远处服务器上的后端进程在通信。两边隔着网络，没法共享内存，所以依靠`socket`来传数据。而数据怎么打包、怎么传、怎么确认对方收到了，有一套双方都遵守的规则，这就是接下来要说的网络协议。
## 网络协议
网络协议这里讲其中三层，分别是应用层,传输层,网络层。这三层不是相互独立的，它们共同解决数据内容怎么表示、怎么保证不丢、怎么找到对方这几回事。

应用层，管的是传输什么内容、内容要遵循什么样的规范。相关的协议有超文本传输协议 HTTP和加密版本 HTTPS，定义了浏览器请求与服务器响应的各是长什么样子。

传输层，管的是怎么把数据送到对方的进程。这一层有两个主要的协议：TCP 和 UDP。TCP 存在三次握手机制，即请求 -> 同步确认 -> 确认，数据丢了会重传，乱了会重新排序，这保证了数据的完整性和可靠性；UDP 不建立连接，也不保证送到，所以数据可能乱序与重复发送，但胜在快，常用于视频通话、直播这类场景。HTTPS目前主流跑在TCP上。

网络层，管的是怎么找到对方。每台联网的设备都有一个 IP 地址，数据被切成一个个小包，在多台路由器间接力转发，每个路由器只管把包往离目的地更近的方向送一步，最终抵达对方。

现实生活中，为啥在浏览器里输入域名而不是 IP，也能得到响应呢？这其实是 DNS 协议的功劳，有专门的域名服务器，负责把域名解析成对应的 IP 地址。而家里常备的路由器，则遵循 DHCP 协议掌管 IP 的分配：我们连上 WiFi 后，路由器会自动给设备分配一个 IP，这个 IP 存在租约时间的机制，即设备使用ip一段时间后再续约。
## 前端
输入域名后，我们得到了对应的数据，接着浏览器会在这个窗口里运行其中的前端文件：它们负责在浏览器这个进程中进行页面的渲染，以及后续怎么继续与后端服务器之间进行通信。现在AI生成的前端文件通常是本地的，缺少与后端服务器进行交互的代码，所以仅实现页面的渲染。

前端文件的编写，可以直接靠前端三件套，也可以用 Vue 或 React 框架。用框架写的代码，浏览器没法直接运行，后续要通过 Vite 配上对应的插件，构建成一个 HTML 加若干 JS/CSS 分包，再放到服务器上，等浏览器请求时由服务器发送过去。

## 后端
后端一方面要监听来自客户端的请求，另一方面还要与数据库保持连接。数据库本身也是一个独立的进程，后端与数据库之间不再使用 HTTP 通信，而是直接基于 TCP，采用数据库自身的专有协议来维持长连接。IP 地址负责定位到机器，端口号则负责指明机器上的具体服务。例如 MySQL 默认使用 3306，PostgreSQL 默认使用 5432，Redis 默认使用 6379，MongoDB 默认使用 27017，而 HTTP 和 HTTPS 的默认端口分别是 80 和 443。
```bash
# 前端到后端（HTTP 协议）
https://www.white66.top:443/api    # 默认端口 443，省略不写

# 后端到数据库（MySQL 协议）
mysql://127.0.0.1:3306         # 数据库的 IP(本机)与端口
```

但数据库能同时承载的连接数是有上限的，无法应对海量的并发请求，因此出现了两项常见的优化技术。其一是连接池：后端预先建立好固定数量的数据库连接并放在池子里，需要时取一条，用完再归还，避免了反复建立和断开连接的开销，也把连接总数控制在数据库能承受的范围内。其二是数据库设计中的索引：它让查询不必逐行扫描整张表，从而缩短每次查询的耗时。

为了解决服务器在一秒可能处理非常多请求(即高并发)这个问题，存在很多厉害的技术实践：首先是量大管饱采用服务器集群，多台服务器由Nginx做负载均衡，分发请求；其次是用Redis缓存数据，以此减轻数据库压力；抑或是消息队列做异步处理；搭配限流与熔断等保护手段。在此基础上，大型系统还会采用微服务架构，把不同业务拆开独立部署，按需单独扩容。

为了学习这些，需要了解缓存穿透、缓存击穿、缓存雪崩，TTL、分布式锁，原子操作、主从复制、哨兵等概念。真的还蛮复杂的，对吧。

后端开发通常会借助成熟的框架来完成路由、请求解析、参数校验等通用工作，不同语言各有主流选择，例如 Go 的 Gin，Java 的 Spring Boot，Python 的 FastAPI。并用Docker进行环境打包。
## 完整项目
一个完整的全栈项目还需要用 Git 做版本管理，记录每次代码改动，方便回溯和协作。同时还需要 CI/CD，把构建、测试、部署串成一条自动化流水线：代码提交后就自动完成构建、跑测试，并在通过后部署上线。

回到开头的问题：浏览器里的跳转、QQ 里弹出的消息、手机里各种 APP，到底是靠什么搭起来的？把整篇串起来，其实就是一件事：不同机器上的进程，按照约定好的规则互相通信。
```text
输入域名 → DNS 解析出 IP → TCP 建立连接 → 发送 HTTP 请求 → 后端进程处理 → 返回响应 → 浏览器渲染页面
```
